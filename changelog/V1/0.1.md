# 0.1.8 — Honeypot trap channel

_2026-06-08_

## Added
- **Honeypot:** designate trap channel(s) nobody legitimate should post in. A non-exempt member
  who posts there is **muted**, has their recent messages **purged server-wide**, and a
  configurable **ping** fires — all editable from the dashboard.
- **Mute method** is selectable: a **mute role** (stays forever) or a native **timeout** (length
  configurable, Discord-capped at 28 days).
- **Purge window** (minutes back, default 10) scans every readable channel and bulk-deletes the
  offender's messages within the window; **0 disables** purging.
- **Ping target** is a user (you), a role, or none, posted to a chosen **alert channel**.
- **Exemptions:** staff (Moderate Members) and bots are always immune; extra exempt roles editable.
- Optional **auto-ban** and **DM-the-offender** toggles (both off by default).
- Trips recorded to `honeypot_actions` (shown on the page) + `track()`: `honeypot.triggered`.
- **Dashboard → Honeypot** (Moderation) + Overview module tile; included in config backups.
- Tables: `honeypot_config`, `honeypot_actions` (migration `0026`).

## Verified
- `tsc` clean · `next build` clean.

# 0.1.10 — Smart reply: AI image generation

_2026-06-12_

## Added
- **AI picture generation** in smart-reply: when someone asks the bot for a picture/photo/drawing,
  it can now reply with a generated image. Two-stage trigger — a cheap **keyword gate** on the
  message offers the model the option, and the model decides by ending its reply with an
  `IMAGE: <prompt>` line; that line drives generation while the rest becomes the caption.
- **Free image backend via Pollinations** (no API key, zero config) behind a **provider seam**
  (`src/server/integrations/image-gen/`) so Cloudflare Workers AI / others can drop in later.
  Optional `POLLINATIONS_TOKEN` env unlocks higher rate limits.
- Separate **per-guild daily image cap** (default 25, `0` = unlimited) — the image API is the
  real cost/abuse vector, so it's capped independently of text replies.
- `/ai images` subcommand (toggle + daily cap) and a new **Images** line in `/ai status`.
- New columns on `smartreply_config`: `images_enabled`, `image_provider`, `image_daily_cap`
  (migration `0027`). `track()`: `smartreply.image`.

## Verified
- `tsc` clean · `next build` clean.

# 0.1.11 — Smart reply: pivot picture-gen to math rendering

_2026-06-12_

Pollinations moved keyless image generation behind a paywall (HTTP 402 on shared hosts), and the
real ask was rendering **math equations as images**, not AI art — so the feature was repurposed.

## Changed
- The conversational trigger is unchanged (ping the bot + ask), but the model now ends its reply
  with a `MATH: <LaTeX>` line instead of `IMAGE:`, and we render that LaTeX to a clean equation
  image. Non-math requests just get a normal text reply.
- **Renderer is now CodeCogs** (`src/server/integrations/math-render/`, behind a provider seam) —
  free, **keyless, and not rate-limited** (a stateless LaTeX typesetter, unlike image-gen APIs).
- On a render failure or daily-cap hit the bot replies with a clear note instead of a caption that
  implies an image was attached.
- `/ai images` → **`/ai math`** (toggle + daily cap); `/ai status` shows a **Math images** line.
- Existing `smartreply_config` columns are reused (no migration); `image_provider` is now legacy.
  `track()`: `smartreply.math`.

## Removed
- The Pollinations integration (`src/server/integrations/image-gen/`) and `POLLINATIONS_TOKEN` env.

## Verified
- `tsc` clean · `next build` clean.
