# v0 — Phase 0: Foundation

_2026-06-02_

The deployable skeleton. No user-facing features yet — this is the infrastructure every later
phase plugs into: the bot boots, the dashboard logs in, health and logs are live, and it ships
to Render. Built from scratch as the v2 rebuild of the old `Discord-bot`.

## Added

### Project & tooling
- Next.js 16 + TypeScript (strict) + Tailwind, npm.
- Dependencies: discord.js v14, Drizzle ORM + `@libsql/client` (SQLite), Auth.js v5 (next-auth), zod, dotenv.
- Scripts: `db:generate`, `db:migrate`, `db:studio` (Drizzle Kit).
- `serverExternalPackages` for the Node-only libs (discord.js, libsql).

### Architecture
- **Monolith**: the Discord bot boots inside the Next.js server via `src/instrumentation.ts` — one process, one deploy, shared types & DB.
- **Layered structure** (see `planning/09-project-structure.md`): `app` (UI) · `server/{core,db,integrations,features,jobs}` (backend) · `lib` (pure).

### Database
- Drizzle + libsql; local SQLite file now, Turso-ready later.
- 8 tables: `guilds`, `accounts`, `feature_toggles`, `audit_log`, `logs`, `scheduled_tasks`, `analytics_events`, `analytics_daily`.
- Initial migration generated and applied; migrations run automatically on boot.
- All timestamps stored as UTC epoch-ms.

### Core services (`src/server/core`)
- **Logger** — structured logs to the DB + an in-memory ring buffer + an event bus (feeds the live page), with retention-based pruning.
- **Health** — uptime, memory, DB check, Discord status, API states.
- **Analytics** — `track()` sink writing `analytics_events` (the day-one instrumentation seam; no features emit yet).
- **Permissions** — resolves a Discord user's dashboard access level (owner/admin/mod/viewer) from their guild role.

### Discord (`src/server/integrations/discord`)
- Gateway client with the right intents/partials, kept as a single HMR-safe instance.
- `/ping` slash command + guild command registration.
- Event handlers split out: `ready`, `interaction-create`, error logging.
- Graceful offline mode — with no token, the bot stays down and the dashboard still runs.

### Dashboard (`src/app`)
- Discord OAuth login (Auth.js), role-gated dashboard layout, sign-out.
- **Overview** — at-a-glance status + what's next.
- **Bot Health** — live telemetry, auto-refresh every 5s.
- **Logs** — live feed over SSE with level/text filters and a connection indicator.
- API routes: `/api/auth/*`, `/api/health` (guarded), `/api/logs/stream` (SSE).

### Deployment
- `Dockerfile` (multi-stage) + `.dockerignore` — host-agnostic image.
- `render.yaml` — Render web service + 1 GB persistent disk for the SQLite file.
- `.env.example` documenting all env vars.

### Docs
- `planning/00`–`09` (vision, architecture, hosting, data model, roadmap, features, open questions, scope-headroom, analytics, project-structure).
- Root `README.md` and `CLAUDE.md` conventions.

## Verified
- `npx tsc --noEmit` — clean.
- `npm run build` — clean (8 routes).
- Dev server boots, migrations apply on startup, landing page renders, `/api/health` returns 401 without auth.
